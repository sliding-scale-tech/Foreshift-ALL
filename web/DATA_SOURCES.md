# Data sources — per page

Where each page of the web app gets its data. **Rule: the web app reads Convex only, never Bubble.**
Bubble keeps working exactly as before; the cron chain (events → weather → resolvedDemand) now writes to
both Bubble and Convex, and this app reads the Convex copy.

How this was derived: Convex backend code (`my-app/convex/*`) plus **read-only** inspection of the Bubble
editor (`foreshift-ai`, page `dashboard`; nothing was edited). Every claim carries a confidence level:

- **Confirmed** — read directly from code or from a Bubble element/workflow.
- **Inferred** — follows from the backend contract and the numbers in the design screenshots, but the
  Bubble element binding itself was not opened.
- **Unknown** — needs the owner's input (listed in the last section).

## 2. Daily Outlook (`/dashboard`)

### How Bubble builds this page (Confirmed)

1. Page load runs the backend workflow **`Create Daily Data`**.
2. That workflow calls Convex **`POST /demand/outlook`** with `{ zone, concept, type: "today" }`
   (operator's zone + concept).
3. The response is written into Bubble tables: **`Demand Drivers`** (the driver list), **`Daily Data`**
   (narration, per-daypart notes, weather percents), and it back-fills `ResolvedDemand.{daypart}_percent`
   with each daypart's `combined_percent`.
4. The page's screen group is a `ResolvedDemand` row chosen by URL param `d`; the chart and cards read it.

So the page is really "`/demand/outlook` `today` response + the `ResolvedDemand` row", with Bubble tables
acting as a cache. The web app does the same thing inside Convex (§4): same computation, cached in
`outlookCache`.

### Component → source (what the web app actually reads — implemented)

Everything below is read from Convex only. Two reactive reads feed the page: `operators.getMine`
(header) and `outlookApp.getMine` (everything else; generated by `outlookApp.ensure` when missing/stale —
see §4). `outlookApp.getMine` returns the cached `TodayOutlookResult` + the raw per-daypart weather.
Mapping code: `app/(app)/dashboard/outlook-data.ts` (`toDailyOutlook`); hook: `app/hooks/useDailyOutlook.ts`.

| UI component | Web app reads (Convex) | Bubble equivalent | Status |
| --- | --- | --- | --- |
| Header "Today's Demand Forecast For {name}", date · name · concept | `operators.restaurantName`, `operators.conceptType`; date = Detroit clock (or `?date=`) | Operator record + current date | Done |
| Operations brief text | `outlookCache.result.narration` (Gemini, generated once per zone × concept × date) | `Daily Data` narration | Done |
| Banner band + score | `result.peak.band`, `result.peak.score` — the **peak daypart** (owner-confirmed; equals `resolvedDemand.peakBand/peakScore`) | `ResolvedDemand` peak fields | Done |
| Score bar (0–150) | constant `MAX_SCORE = 150` | same | Done |
| Daypart card title + window | static constants in `outlook-data.ts` (Bubble's `daypart` option set: Display / Duration) | option set | Done |
| Daypart band pill | `result.dayparts[i].band` | `ResolvedDemand.{daypart}_band` | Done |
| "+X% vs. normal" | `result.dayparts[i].combined_percent` (needs base score → `demandScores`) | `ResolvedDemand.{daypart}_percent` (back-filled by Bubble) | Done |
| Weather name + temp per daypart | `weatherSignals.{morning,midday,dinner,late}.{condition,tempF}` via `outlookApp.getMine.weather`; "No forecast" if the day has no row | `WeatherSignal` | Done |
| "Event Lift" note | `result.dayparts[i].event_note` (Gemini) | `Daily Data` notes | Done |
| Daypart Demand Chart | `result.dayparts[i].score` × 4 (same values as `resolvedDemand.{morning,midday,dinner,late}Score`); x labels Breakfast / Lunch / Dinner / Late Night; Apex options copied from Bubble's element (§ below) | `ResolvedDemand` 4 score fields | Done |
| Top Demand Drivers | `result.drivers` (top 5 by lift, from `eventSignals` + `weatherSignals`), filtered `lift_percent ≥ 0`; event subtitle = venue + start time in Detroit tz | `Demand Drivers` table (same filter) | Done |

Verification so far: the Convex-only `today` result for Downtown Detroit (Core) × Fine Dining was compared
with the Bubble-fed `/demand/outlook` result — dayparts, drivers, day summary and peak were identical, and
the scores match the `resolvedDemand` row. The page was rendered with that real JSON (auth bypassed
temporarily). **Not yet exercised:** the signed-in `getMine` → `ensure` round trip in a real session.

**Known differences from Bubble (not yet done):**
- Weather icon is always the cloud icon; Bubble's condition → icon mapping was not inspected.
- Driver icons are only event vs. weather (stadium / rain-sun illustrations).
- No day switcher (Bubble's navbar day cards → `d` param); the page accepts `?date=YYYY-MM-DD` only.

Not used by the current design but available in the cached result: `day_summary`, `event_narration`,
`weather_narration`, `dayparts[i].weather_percent`, `dayparts[i].base_score`.

### Chart config (Confirmed, from Bubble's Apex Chart element — now applied in `app/components/DemandAreaChart.tsx`)
Area chart, height 350, toolbar off, legend top/right ("Demand Score"), grid on, data labels off,
`stroke` smooth width 3 colour `#027FFC`, fill solid `#027FFC33` opacity 0.25, markers size 4 colour
`#2F45C5` with white stroke width 2 (hover 6), axis borders hidden. (Y-axis is fixed to 0..next multiple of

### Day switching (`d` URL param) — Unknown how Bubble generates it
`/demand/outlook` accepts an optional `date` (`YYYY-MM-DD`), but only inside the current Mon–Sun week.
The web app can use `?date=YYYY-MM-DD` and default to today. How Bubble's navbar/day cards feed `d` was
not inspected.

## 3. Weekly / Events / Weather (built 2026-09-21)

All three read Convex only, through two reads: **`outlookApp.getWeek`** (live, reactive; the operator's Mon..Sun
week from `resolvedDemand` + `weatherSignals` + `eventSignals`, no AI) and **`outlookApp.getMine`** (cached AI
outlook per type/date, generated by `outlookApp.ensure`; §4). The Convex outlook results for `weekly`, `events`
and `weather` were compared with the Bubble-fed `/demand/outlook` path for the same zone × concept — identical
apart from the AI text. (A real difference was found and fixed: the event mirror stores times as `18:40:00`,
Bubble as `18:40`; the loader now normalizes.)

### Event Outlook (`/events-overview/[eventId]?date=`)
Read with **`outlookApp.getEventImpact({eventId, date})`** (live query, no AI, scoped to the operator's zone × concept).
Same math as `POST /event/impact` (`eventImpact.ts`), reading Convex instead of Bubble: lift = magnitude × affinity ×
proximity (coefficient tables; the raw coefficients are not returned).
| UI | Source |
| --- | --- |
| Event card (date, icon, name, venue, time, type) | `eventSignals` row |
| Left band pill | `impactBand` = band of (headline daypart base score + this event's lift), capped at 150 |
| Left big % | `headlinePercent` = lift ÷ headline daypart base score |
| Daypart "+X%" | `dayparts[].percent` = lift ÷ that daypart's base score (`demandScores`); 0 on dayparts the event doesn't fall in |
| Daypart band pill + score | the day's `resolvedDemand` `{daypart}Band/Score` |

Checked: 189.4% for the Tigers game matches the Bubble-fed `/event/impact` result for the same zone × concept.

## 4. Convex-only outlook layer (built and deployed 2026-09-21)

All additive; Bubble and the existing `/demand/outlook` endpoint are untouched.

| Piece | Where | What it does |
| --- | --- | --- |
| `demandScores` table | `schema.ts` | Base score/band per zone × concept × day × daypart, same wide shape as Bubble's `DemandScore` (819 rows). Was not in Convex before — every reader called Bubble. One-off upload from `convex/data/baseDemand.json` (built from `foreshift_base_demand_wide.csv`, the file Bubble's table was loaded from) via `outlookApp:seedDemandScores`. **Loaded: 819 rows.** |
| `outlookCache` table | `schema.ts` | Generated outlook JSON (incl. Gemini text) per zone × concept × type × date, with a fingerprint of the numeric inputs (the role of Bubble's Daily/Weekly/Event data tables) |
| `OutlookInputs` | `lib/outlook.ts` | Optional `inputs` on `compute{Today,Weekly,Event,Weather}Outlook` so the *same* math and narration run off Convex rows instead of Bubble reads |
| `outlookApp.getMine` | query | Caller's cached outlook (`type`, `date?`) + `fresh` flag + raw per-daypart weather. Zone/concept come from the caller's `operators` row |
| `outlookApp.ensure` | action | Generates + caches when missing or stale; no-op when fresh |
| `outlookApp.getWeek` | query | The operator's Mon..Sun week (peak demand, weather, events) for the Weekly / Events / Weather pages |
| `outlookApp.getEventImpact` | query | One event's isolated impact per daypart (Event Outlook page) |
| `useDailyOutlook` | `web/app/hooks` | Query + one-shot `ensure`, maps to the page's `DailyOutlook` shape |

Weekly / Events / Weather pages reuse `getMine` / `ensure` with `type: "weekly" | "events" | "weather"`.

**State:** deployed to `neat-frog-865`; `demandScores` loaded (819 rows). If the base scores ever change, edit
the CSV, regenerate `baseDemand.json`, and re-run `npx convex run outlookApp:seedDemandScores` (idempotent).
